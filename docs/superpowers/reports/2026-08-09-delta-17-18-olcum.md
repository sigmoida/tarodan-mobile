## 3. Takas v2 — deploy edilmiş, hem v1 hem v2 kayıt var

`GET /trades` (10 takas): `cashPayments` alanı **hepsinde var**, uzunlukları
0 / 1 / 2 karışık.

### v2 takas (2 satır) — `c3300977-…`

```jsonc
"cashAmount": 500,
"cashPayerId": "52336236-…",
"cashCommission": null,
"cashPayments": [
  { "id": "d3ac9b47-…", "payerId": "2a882a6f-…", "recipientId": null,
    "amount": 0,   "tradeFeeAmount": 200, "shippingAmount": 200,
    "commission": 0, "totalAmount": 400, "status": "pending",  "paidAt": null },
  { "id": "4824e452-…", "payerId": "52336236-…", "recipientId": "2a882a6f-…",
    "amount": 500, "tradeFeeAmount": 200, "shippingAmount": 200,
    "commission": 0, "totalAmount": 900, "status": "refunded",
    "paidAt": "2026-08-05T11:46:15.052Z" }
],
"paymentDeadline": "2026-08-07T11:45:58.846Z"
```

Delta 17 §1a'nın tarif ettiği şeklin aynısı: `recipientId` fark taşımayan satırda
`null`, `commission` her iki satırda 0, `totalAmount = amount + tradeFeeAmount +
shippingAmount` (400 = 0+200+200, 900 = 500+200+200). `cashCommission` `null`.

**Tekil `cashPayment` alanı da v2 alanlarını taşıyor** (birincil satır = fark
taşıyan satır) — yani tekil alanın varlığı v1 işareti DEĞİL.

### v1 takas (1 satır) — `12012f5e-…`

```jsonc
"cashAmount": 150,
"cashCommission": 7.5,
"cashPayments": [
  { "id": "b2f9029d-…", "payerId": "52336236-…", "recipientId": "2152e919-…",
    "amount": 150, "tradeFeeAmount": 0, "shippingAmount": 0,
    "commission": 7.5, "totalAmount": 157.5, "status": "pending" }
]
```

Ayırt edici: `commission > 0`, `tradeFeeAmount`/`shippingAmount` sıfır,
`cashCommission` dolu. `payment-quote` bu takasta **200 + boş gövde** döndü —
delta 17 §1c'nin dediği gibi.

### ⚠️ Planın `isV2` kuralı EKSİK

`145abe9e-…` (status `rejected`, `cashPayments: []`) için `payment-quote`
**dolu gövde** döndürdü. Yani:

| `cashPayments.length` | Anlam |
| --- | --- |
| ≥ 2 | Kesin v2 (kabul sonrası) |
| 1 + `commission > 0` | v1 |
| 0 | **Belirsiz** — kabul edilmemiş v2 takas da 0 satırlıdır |

Planın Görev 4'ündeki `isV2 = cashPayments.length >= 2` kuralı, **kabul
edilmemiş v2 takasları v1 sayar**. Delta 17 zaten iki sinyal söylüyordu ("kabul
sonrası 2 satır, **veya** kabul öncesi `payment-quote` boş olmayan gövde") —
plan bunun yalnız ilk yarısını uyguluyordu. Plan buna göre düzeltildi
(bkz. aşağıdaki "Plana yansıyanlar").

## 4. `GET /trades/:id/payment-quote` — dokümandan FAZLA alan dönüyor

```jsonc
{
  "tradeId": "c3300977-…",
  "commissionRuleSet": { "id": "8d9fe2c4-…", "version": 1 },   // ⬅ dokümanda YOK
  "ruleMatches": [                                              // ⬅ dokümanda YOK
    { "productId": "d22c10ef-…", "side": "initiator",
      "ruleId": "local-rule-…-premium-10000-24999",
      "ruleName": "Araba / Premium / 10.000-24.999 TL",
      "sellerType": "PREMIUM", "matchedAmount": 10000,
      "minAmount": 10000, "maxAmount": 25000,
      "tradeFeeSellerAmount": 100, "tradeFeeBuyerAmount": 100 }
  ],
  "initiator": {
    "serviceFee": 200, "shipping": 200, "cashDifference": 0, "total": 400,
    "feeLines": [ { "productId": "d22c10ef-…", "role": "seller", "amount": 100 },
                  { "productId": "57ebfe79-…", "role": "buyer",  "amount": 100 } ],
    "userId": "2a882a6f-…", "side": "initiator"
  },
  "receiver": { /* aynı şekil */ "cashDifference": 500, "total": 900 }
}
```

`total = serviceFee + shipping + cashDifference` doğrulandı (400 ve 900).
`commissionRuleSet` + `ruleMatches` **additive**; plandaki tip yalnız
`initiator`/`receiver` okuduğu için değişiklik gerekmiyor — ama tipe yorum
düşülsün ki ileride "eksik alan" sanılmasın.
