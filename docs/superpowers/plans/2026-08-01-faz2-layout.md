### Task 1: Mesaj listesi okurken dibe fırlamasın (B3, Yüksek)

En değerli düzeltme. Kullanıcı konuşma geçmişini yukarı kaydırıp okurken, bir görsel yüklenince veya yeni sayfa gelince liste kendiliğinden en alta atıyor — okunan yer kayboluyor.

**Kök neden:** `app/messages/[threadId]/_hooks/useMessageThread.ts:73-83` `handleContentSizeChange`'in `else` dalı **koşulsuz** `scrollToEnd({ animated: true })` çağırıyor. Kullanıcının o an nerede olduğuna bakılmıyor.

**Files:**
- Modify: `app/messages/[threadId]/_hooks/useMessageThread.ts:73-83`
- Modify: `app/messages/[threadId]/_components/MessageList.tsx` (scroll pozisyonu takibi gerekiyorsa)
- Test: `app/messages/[threadId]/__tests__/` altında

**Mevcut kod:**
```ts
const handleContentSizeChange = () => {
  if (!isPositioned) {
    if (messages.length > 0 || !isLoadingMessages) {
      scrollViewRef.current?.scrollToEnd({ animated: false });
      setIsPositioned(true);
    }
  } else {
    scrollViewRef.current?.scrollToEnd({ animated: true });
  }
};
```

**İSTENEN DAVRANIŞ — sözleşme:**

| Durum | Ne olmalı |
|---|---|
| İlk yükleme (`!isPositioned`) | Bugünkü gibi animasyonsuz dibe konumlan |
| Kullanıcı **dibe yakın** (eşik içinde) + içerik büyüdü | Dibe kaydır (yeni mesajı göster) |
| Kullanıcı **yukarıda okuyor** + içerik büyüdü | **KAYDIRMA** — pozisyonunu koru |
| **Kullanıcının kendi gönderdiği mesaj** | Nerede olursa olsun **her zaman** dibe kaydır |

⚠️ **Son satır kritik.** Kendi mesajını gönderip ekranın gitmemesi, bugünkü hatadan daha kötü bir kullanıcı deneyimi. Gönderme akışında (`useMessageThread`'de `setInputText('')` yapılan yer, ~satır 155) açık bir "zorla dibe kaydır" bayrağı kullan — `onContentSizeChange`'in eşik mantığına bırakma.

**Yaklaşım:** `onScroll` ile son offset'i bir `ref`'te tut (state değil — her scroll'da render tetiklemesin), `contentSize.height - layoutMeasurement.height - contentOffset.y < EŞİK` ise "dibe yakın" say. `EŞİK`'i `theme.spacing[n]`'den türet veya bir `_lib/` sabiti yap; ham sayı gömme.

Raporun önerdiği alternatifler (`inverted` FlatList, `maintainVisibleContentPosition`) daha temiz ama daha riskli — mevcut `isPositioned` kalıbını, ilk konumlanmayı ve `TypingIndicator` footer'ını yeniden kurmayı gerektirir. **Eşik yaklaşımını seç**; alternatifi seçeceksen önce gerekçeni raporla.

- [ ] **Step 1: Testi yaz** — dört durumu da kapsasın (yukarıdaki tablo). `scrollToEnd`'in çağrıldığını/çağrılmadığını mock ile doğrula.
- [ ] **Step 2: Kırmızı olduğunu gör** — `npx jest app/messages/ --ci --silent --forceExit`
- [ ] **Step 3: Uygula**
- [ ] **Step 4: Yeşil**
- [ ] **Step 5: Commit**

```bash
git commit -m "fix(messaging): stop yanking the thread to the bottom while reading

onContentSizeChange scrolled to the end unconditionally, so an image
finishing its load or a page of history arriving threw the user back down
mid-read. Only auto-scroll when they are already near the bottom, and keep
an explicit force-scroll for messages they send themselves."
```

### Task 4: Arama başlığının tahmini yüksekliği (B6, Orta — EN RİSKLİ, SONA)

Arama sekmesine girip sonuçlar gelince ilk ürün satırı bir anlık yanlış yerde duruyor ve hemen kayıyor.

**Kök neden:** liste üst boşluğu, üstteki absolute arama/filtre çubuklarının **tahmini** yüksekliğinden geliyor (`COLLAPSIBLE_ESTIMATE = 180`, `app/(tabs)/_lib/searchConstants.ts:10`). Gerçek yükseklik `onLayout` ile ölçülüp state'e yazılıyor (`app/(tabs)/_hooks/useSearch.ts:117,128`) ve doğrudan `contentContainerStyle.paddingTop`'a besleniyor (`app/(tabs)/search.tsx:60`). Ölçüm 180'den farklı çıktığı anda liste yeniden yerleşiyor.

**Neden en riskli:** `useSearch` scroll/collapse mantığına dokunuyor. Çubuklar kaydırıldıkça daralıyor; sabit bir yükseklik vermek bu davranışı bozabilir. **Önce `useSearch`'ün collapse mantığını tamamen oku ve anla.**

**Yaklaşım seçenekleri (gerekçeli seç, raporla):**
1. Çubuklara stylesheet'te **verilen** sabit bir yükseklik — `onLayout` düzeltmesi hiç tetiklenmez. En temiz, ama collapse davranışını bozmamalı.
2. İlk ölçüm gelene kadar listeyi gizle — mesaj ekranının `isPositioned` kalıbı (`MessageList.tsx:135`) bu repoda zaten var, kopyalanabilir.
3. `COLLAPSIBLE_ESTIMATE`'i gerçek ölçümle uyumlu hale getir — kırılgan, önerilmez.

Ayrıca `isLoading` dalı FlatList'i tamamen ortalanmış bir Spinner ile değiştiriyor (`app/(tabs)/search.tsx:48-55`); dönüşte liste sıfırdan yerleşiyor. Bunu `ListEmptyComponent` içine taşı ki liste hiç sökülmesin.
